# Writing guide

Everything on this site should sound like Rushang explaining his work to another engineer.

## Voice

Say what you did, then what you used. Use "I". Use short, plain sentences and name the real tools. If you wouldn't say a line in an interview, rewrite it.

Sounds right:

> I used another agent to parse call transcripts and the report repository into YAML and Markdown.

> A project built as part of my Analysis of Algorithms class at the University of Florida.

## Rules

- Headlines say what the section is. No slogans.
- Don't set up a contrast nobody asked about. State the point.
- Don't end a paragraph with a line that repeats it.
- Don't use bold labels at the start of paragraphs.
- Don't use a list of three unless there are three things.
- Use numbers and tool names in place of adjectives. If there's neither, cut the line.
- Each project page needs at least one detail that only the person who built it would know, such as a bug or a choice that had a cost.
- Say when something wasn't measured.
- Skip stat tiles unless the number is a real result.

## Before publishing

Read the page out loud. Then check every number and name against its source.
