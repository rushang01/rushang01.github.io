## Problem

This was my project for CAP5771 in Spring 2025. Restaurant reviews for Bangalore sit on different platforms, and nothing combined the ratings and review counts from Zomato and Swiggy. I wanted a tool where you enter a cuisine, area and budget and get a ranked list.

## My role

I did this alone, from collecting the data to building the Streamlit app.

## Architecture

The three sources merged into 14,393 rows. I enriched those through the Google Places API, dropped duplicates by `place_id` and joined back on name and address, which left 9,848 restaurants.

TF-IDF on cuisines, location and place types gives the content score. SVD on a location-by-restaurant matrix gives the collaborative score. Popularity mixes rating, rating count and inverse cost at 0.6, 0.3 and 0.1.

## Key decisions and trade-offs

The Swiggy file was almost 1 GB, so I streamed it with `ijson`.

The data has no user history, so I used location as a stand-in for the user. That's a big simplification, because it picks up area trends and misses individual taste, but it let me try collaborative filtering at all.

The final weights are 0.60 content, 0.30 popularity and 0.10 collaborative. Content and popularity were stronger signals than location in this data.

Without user interactions I couldn't use standard ranking metrics, so I wrote two of my own: rating precision and cuisine match rate.

## Failures and limits

Collaborative filtering scored 0.998 on rating precision but 0.133 on cuisine match. It found restaurants with similar ratings that served different food.

Rating precision is looser than my report says. The report describes it as within ±0.5 of the source rating, but the code only checks the lower bound, so anything rated higher also counts.

I had no real user feedback, so there's no true train and test split on user interactions. These numbers measure relevance and can't tell you whether anyone would like the recommendations.

Popularity carries a lot of weight, so well-known places get favored. New restaurants and new locations have a cold-start problem, and the data is a static snapshot.
